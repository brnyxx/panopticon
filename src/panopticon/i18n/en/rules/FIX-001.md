# FIX-001 — Secure credential reference

## Problem
A configuration value is identified as a credential-shaped environment value or remote header, or as a high-entropy environment value. The value is selected by an exact configuration pointer; the credential itself is not recorded.

## Impact
Keeping the value inline can expose a credential to configuration readers or backups. The risk applies when the value is active or grants access to a service.

## Evidence
The related CFG-001, CFG-007, or CFG-011 finding records the configuration pointer, environment key or header name, and classification without persisting the secret value.

## Recommended action
Run `pano fix` and select FIX-001. With a complete OS credential-store backend, the value is stored there and replaced by a `${KEY}` reference. For clients without environment-reference support, use wrap-injected environment values sourced from `SecretStore` and consider `pano install`. If no secure backend is available, or the choices are declined, the result is guidance only; no secret-bearing file is written.

## How to verify
Run `pano doctor` and confirm that the related CFG-001, CFG-007, or CFG-011 finding is absent for the installation. Check that the configuration contains `${KEY}` rather than the credential value and that no plaintext environment file was created.

## Limits
This rule does not prove that a credential is valid, active, or revoked, and it does not prove that every copy outside the observed configuration was removed. Unsupported or incomplete observation remains `UNKNOWN`. A credential-store capability is required for an automatic change; guidance-only output does not remediate the secret.
