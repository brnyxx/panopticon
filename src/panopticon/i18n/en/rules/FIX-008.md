# FIX-008 — Protocol-validated HTTP-to-HTTPS replacement

## Problem
A remote MCP entry uses a plaintext `http` URL. FIX-008 can replace that URL with its `https` form only after a protocol check.

## Impact
Requests made over plaintext HTTP can be observed or altered by a network intermediary. This matters when the remote endpoint and the client communicate across a network that does not provide equivalent transport protection.

## Evidence
CFG-008 records the URL value and its exact configuration pointer. Before planning the replacement, Panopticon sends a bounded `POST` MCP `initialize` request to the HTTPS candidate; a successful check requires a 2xx response containing JSON-RPC `2.0`, `id` `1`, and a string `result.protocolVersion`.

## Recommended action
Run `pano fix --rule FIX-008`, review the proposed URL diff, and apply it. `HEAD` responses, generic HTTP success, redirects, or a response without the required MCP fields are insufficient, so the action remains guidance-only when the check does not pass. Keep the journal ID and undo exactly with `pano fix --undo <20-hex-journal-id>` if needed.

## How to verify
Run `pano doctor` and confirm CFG-008 is absent for the edited pointer and that the URL uses `https`. To undo, run `pano fix --undo <20-hex-journal-id>` and compare the configuration's SHA-256 hash with the pre-change hash.

## Limits
This change does not prove endpoint identity, application authorization, availability, or safety beyond the bounded initialize response. It does not validate every path or request, and it does not cover URLs with embedded credentials or credential query keys.
