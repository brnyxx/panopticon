# SENT-007 — 검증되지 않은 도구 매니페스트

## 문제
신뢰할 수 있는 무결성 검사를 먼저 수행하지 않은 채 매니페스트 바이트가 도구 등록 또는 로드에 도달합니다. 이 규칙은 해시나 서명 검증보다 앞서 매니페스트를 사용하는 경우를 다룹니다.

## 영향
변조된 매니페스트가 서버에 제시되는 도구나 권한을 바꿀 수 있습니다. 이 결과는 검증 흐름이 없다는 정적 근거이며, 매니페스트가 실제로 수정되었거나 공격이 성공했다는 사실을 입증하지 않습니다.

## 근거
AST 규칙 `sentinel.sent007.unverified-manifest`는 이름에 `manifest`가 포함되거나 이름이 `load_tools` 또는 `register_tools`인 최상위 Python 함수를 검사합니다. `json.load`, `json.loads`, `yaml.safe_load`, `yaml.load` 호출에서 해당 함수 안에 더 이른 인식 가능한 검증 호출이 없으면 표시합니다. 인식되는 검증 호출은 `hashlib.sha256`, `hmac.compare_digest`, 그리고 이름이 `.verify`로 끝나는 메서드입니다.

## 권장 조치
매니페스트를 파싱하고 사용하기 전에 고정된 SHA-256 다이제스트 또는 신뢰할 수 있는 분리 서명을 검증하세요. `sentinel.integrity.yaml`은 버전 `1`을 사용하고, 각 매니페스트마다 지원 모드 하나만 선택하세요(소문자 64자리 SHA-256 또는 Ed25519·RSA-PSS-SHA256·ECDSA-SHA256 서명 메타데이터). 신뢰 기준점 경로는 저장소 상대 경로로 유지하세요.

## 확인 방법
분석되는 함수에서 각 매니페스트 로드 호출보다 먼저 무결성 검사를 추가한 뒤 `pano scan <path>`를 다시 실행하세요. 인식 가능한 검증 호출이 로드보다 앞서면 해당 로드에 SENT-007 결과가 더 이상 생성되지 않아야 합니다.

## 제한
이는 정적 함수 내부 AST 근거이며 암호학적 검증 결과나 런타임 관찰이 아닙니다. 설정된 다이제스트·키·서명·알고리즘이 바이트와 일치하는지는 증명하지 않으며, 별칭·도우미 함수·동적 디스패치·지원되지 않는 API·함수 간 흐름·검사하지 않은 파일에 숨은 검증은 놓칠 수 있습니다. 유효한 무결성 파일은 기준점 검사를 위해 로드되지만 해당 항목이 개별 로드 호출의 데이터 흐름과 연결되는지는 검사하지 않습니다.
