# SENT-002 — 도구 입력에서 안전하지 않은 실행

## 문제
도구가 제어하는 입력이 안전하지 않은 실행 또는 역직렬화 싱크에 도달합니다. 정적 Semgrep 규칙은 형식 지정 여부와 관계없이 MCP 도구 매개변수에서 `eval`, `exec`, `pickle.loads`, `yaml.load`, 또는 셸을 활성화한 `subprocess.run`, `subprocess.call`, `subprocess.Popen`으로 이어지는 흐름을 추적합니다.

## 영향
입력 값이 이러한 싱크에 도달하면 호출자가 해당 경로에서 코드 실행, 역직렬화 또는 셸 명령 해석에 영향을 줄 수 있습니다. 영향은 도달 가능한 경로와 싱크의 실행 방식에 따라 달라집니다.

## 근거
Semgrep 규칙 `sentinel.sent002.unsafe-execution`은 Python MCP 도구 함수에 taint 분석을 적용합니다. 소스 패턴은 MCP 도구 데코레이터가 붙은 동기 또는 비동기 함수의 매개변수이고, 싱크 패턴은 위에 열거한 실행·역직렬화 호출입니다. 결과에는 일치한 소스에서 싱크까지의 위치가 기록됩니다.

## 권장 조치
동적 실행을 명시적 파서와 고정된 명령 허용 목록으로 바꾸세요.

## 확인 방법
`pano scan <path>`를 다시 실행하세요. 검사한 Python 소스에서 MCP 도구 매개변수가 구성된 싱크 중 하나에 도달하지 않으면 SENT-002 결과가 없어야 합니다.

## 제한
이는 정적 taint 증거이며 도구 호출을 관찰한 결과나 입력이 악용되었다는 증명이 아닙니다. 규칙에 구성된 Python 패턴만 다루므로 간접 흐름, 다른 언어, 실행 중 생성되는 코드, 해당 패턴 밖의 싱크는 감지되지 않을 수 있습니다.
