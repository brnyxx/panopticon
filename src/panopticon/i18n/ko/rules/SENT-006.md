# SENT-006 — 라우트 인증 누락 또는 무효

## 문제
분석 대상 HTTP 라우트에 상속된 인증이 없거나, 인식 가능한 자격 증명 검사와 거부 경로를 제공하지 않는 검증기를 사용합니다. 구성된 공개 라우트 목록, 애플리케이션 미들웨어 또는 의존성 분석으로 인증이 확인되지 않는 라우트를 다룹니다.

## 영향
애플리케이션이 요구하는 자격 증명 검사를 거치지 않고 요청이 라우트에 도달하여 무단 작업이나 데이터 접근이 가능할 수 있습니다. 이 결과만으로 실행 중인 서비스에서 인증 우회 요청이 발생했다는 사실은 확인할 수 없습니다.

## 근거
AST 규칙 `sentinel.sent006.route-authentication`은 `get`, `post`, `put`, `patch`, `delete`, `options`, `head` 또는 `api_route` 호출로 장식되고 라우트 인자가 문자열 리터럴인 Python 함수를 검사합니다. 구성된 `public_routes`와 일치하는 메서드, `add_middleware(AuthenticationMiddleware)`를 포함한 모듈, 또는 `Depends`/`Security` 의존성이 토큰·자격 증명·authorization·session 이름을 읽고 `jwt.decode`, `compare_digest` 또는 `.verify`를 호출하며 예외를 발생시키는 함수를 가리키는 경우는 제외합니다. 그 밖에는 데코레이터 위치에 `missing-auth` 일치 결과를 기록합니다.

## 권장 조치
라우트가 실행되기 전에 자격 증명 검증과 명시적인 거부 경로를 요구하세요. 보호된 각 메서드에 신뢰할 수 있는 인증 미들웨어나 의존성을 적용하고, 공개 라우트 구성은 의도적으로 공개한 엔드포인트로만 제한하세요.

## 확인 방법
`pano scan <path>`를 다시 실행하세요. 각 분석 라우트가 `public_routes`에 따라 의도적으로 공개되거나, `AuthenticationMiddleware`를 상속하거나, 거부 경로를 가진 인식 가능한 검증 의존성을 사용하면 SENT-006 결과가 없어야 합니다.

## 제한
이는 정적 함수 내부 AST 근거이며 HTTP 요청을 관찰한 결과나 무단 접근이 성공한다는 증명이 아닙니다. 리터럴 라우트, 나열된 데코레이터 메서드, 구성된 공개 패턴, 직접 호출된 미들웨어 및 인식 가능한 `Depends`/`Security` 검증기 본문만 분석하므로 별칭·사용자 지정 프레임워크·간접 미들웨어·함수 간 검사·동적 라우트·검사하지 않은 파일은 반영되지 않을 수 있습니다.
