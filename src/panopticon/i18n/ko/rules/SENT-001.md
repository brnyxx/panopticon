# SENT-001 — 도구 권한 범위가 지나치게 넓음

## 문제
도구가 핸들러에서 사용하는 범위보다 넓은 파일 시스템 또는 네트워크 접근 권한을 선언합니다. 분석기는 권한 매니페스트에 도구가 없거나 선언된 범위와 정적으로 감지한 사용 범위가 다를 때 이 결과를 보고합니다.

## 영향
선언이 핸들러에 필요한 것보다 많은 자원을 허용하면 코드 경로를 분석한 결과보다 선언된 기능 경계가 넓어집니다. 경로 또는 호스트가 동적으로 정해지면 정확히 비교할 수 없으므로 더 넓은 범위로 처리합니다.

## 근거
AST 분석기는 `sentinel.permissions.yaml`을 읽고 Python MCP 도구 영역을 검사합니다. 인식 가능한 호출에서 리터럴 파일 시스템 읽기·쓰기 경로와 네트워크 호스트를 수집한 뒤 도구의 `filesystem.read`, `filesystem.write`, `network` 선언 범위와 비교합니다. 증거는 해당 호출 또는 도구 영역을 가리킵니다.

## 권장 조치
각 선언 범위를 핸들러에 실제로 필요한 자원으로 좁히세요. `broad_scope_justification`이 있는 넓은 범위는 이 결과에서 제외됩니다.

## 확인 방법
권한 매니페스트를 둔 상태에서 `pano scan <path>`를 다시 실행하세요. 모든 도구가 선언되어 있고 선언 범위가 정적으로 감지한 범위와 일치하거나 넓은 범위의 사유가 있으면 SENT-001 결과가 없어야 합니다.

## 제한
이는 실행을 관찰한 결과가 아니라 정적 AST 증거입니다. 인식된 Python 호출과 리터럴 값만 비교하므로 별칭, 동적 값, 검사하지 않은 파일, 분석한 핸들러 밖의 동작은 나타나지 않을 수 있습니다.
