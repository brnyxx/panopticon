# SENT-011 — 잘못된 스키마 입력 처리

## 문제
서버가 필수 도구 인자를 누락했거나 선언된 타입과 다른 형태로 보낸 요청을 핸들러 실행 전에 거부하지 않고 처리했습니다. 이 동적 규칙은 도구 경계에서 필수 필드와 선언 타입을 처리하는 동작을 다룹니다.

## 영향
잘못된 입력이 핸들러 로직에 도달하면 예기치 않은 결과, 오류 또는 부작용이 발생할 수 있습니다. 실제 영향은 인자와 핸들러, 이후 작업에 따라 달라지며, 이 규칙의 카탈로그 영향도는 Low입니다.

## 근거
고정된 동적 카탈로그는 `SENT-011`을 “Malformed schema input processed”로 정의하고, 누락되었거나 타입이 다른 필수 도구 인자를 서버가 처리한 경우로 설명합니다. 고정된 프로버는 선언된 필수 속성에 기준선 값을 만든 뒤, 필수 필드를 생략하는 제한된 무해 프로브(`__SENTINEL_OMIT__`) 또는 선택한 속성을 `__sentinel_wrong_type__` 객체로 바꾸는 프로브를 수행합니다(삭제·비식별 근거 표시는 `__SENTINEL_WRONG_TYPE__`). 오류가 아닌 응답은 해당 프로브 입력이 처리되었음을 기록할 뿐이며, 그 자체로 보안 판정이나 후속 효과를 입증하지 않습니다.

## 권장 조치
핸들러를 호출하기 전에 필수 필드와 선언된 타입을 검증하십시오. 누락되었거나 타입이 맞지 않는 인자는 중첩된 인자 봉투를 포함해 구조화된 프로토콜 오류로 거부하고, 실행 시 검증 규칙을 공개 입력 스키마와 일치시키십시오.

## 확인 방법
런타임 프로브가 포함된 모드에서 `pano scan <path>`로 제한된 동적 프로브를 실행하십시오. 적용 가능한 각 필수 필드에 대해 SENT-011 누락 및 잘못된 타입 사례를 반복하고, 일반적인 유효 호출은 유지하면서 핸들러 실행 전에 검증이 거부하는지 확인하십시오.

## 제한
이 근거는 실행 중 선택된 도구와 스키마 속성, 프로브 사례만 다룹니다. 프로버는 무해한 표식과 제한된 요청을 사용하므로 모든 잘못된 형태, 선택 필드, 별칭, 동적 디스패치 경로 또는 후속 부작용을 실행하지 않습니다. 객체가 아닌 스키마, 선택되지 않은 도구, 전송 오류 및 스캔하지 않은 파일은 대상 범위 밖에 남을 수 있습니다. 프로브 응답만으로 악용 가능성을 입증할 수 없으며, 오류 하나만으로 모든 잘못된 입력이 거부된다고 볼 수도 없습니다.
